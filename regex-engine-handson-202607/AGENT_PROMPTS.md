# 当日 Claude Code に投げるプロンプト集（講師・参加者用）

このプロンプト集は **Claude Code / Codex どちらでも同じように使える**（固定プロンプトをそのまま貼り付ければ良い）。

本ハンズオンの肝は「**基本設計（SPEC.md）さえ握れば、AI で実装がぱっと立ち上がる**」体験。
そのために、各段で Claude Code に投げるプロンプトを**事前に固定**しておく（即興で書かない）。
規則表（SPEC.md）とコードが1対1なので、設計表を貼ればコードが降ってくる。

> 使い方: 参加者は `start` ブランチで TODO を埋める。詰まったら下のプロンプトを Claude Code に。
> 講師は山場①（ハンズオン本体開始 +20分〜、[README.md](./README.md) の「当日の流れ」参照）でこれを画面共有しながら投入する。`main` ブランチが完成版（答え）。

---

## ① 山場：コア（nullable / derivative）を実装させる

`src/derivative.ts` を開いた状態で：

```
このリポジトリの SPEC.md にある「nullable」と「derivative」の規則表に従って、
src/derivative.ts の nullable と derivative を実装してください。

- 型は src/ast.ts の Re（判別タグ付きユニオン）を使う
- 正規表現ノードの生成は必ず src/normalize.ts の mkAlt / mkConcat / mkStar 経由で行う
  （生のオブジェクトリテラルでノードを作らない）
- derivative の連接則 ∂c(rs) = ∂c(r)·s | (ν(r) ? ∂c(s) : ∅) の nullable 項を必ず入れる
- src/normalize.ts と tests/ ディレクトリは変更しないこと（正規化の実装は次の段で扱う）
- 実装後、tests/spec.test.ts が通ることを確認する（特に「a?b トラップ」）

実装だけ。説明は最小限で。
```

→ 直後に `pnpm test`。**赤かったテストが緑になる瞬間**が山場のカタルシス。
特に `a?b` が通れば連接 nullable 項が正しい証拠。

---

## ② 状態爆発を直す：正規化（ACI）を実装させる

`①` の後、`pnpm bench:redos 16` を実行すると「状態爆発を検知」で打ち切られる
（＝なぜ正規化が要るかの体感。bench 側に安全装置が入っているため OOM やフリーズはしない）。そこで：

```
src/normalize.ts の mkAlt / mkConcat / mkStar に、SPEC.md「正規化（ACI）」の規則を実装してください。
目的は遅延DFAの状態を有限に抑えること（これが無いと (a+)+ で状態が指数爆発する）。

- mkAlt: ∅吸収 / r|r 冪等 / 可換（canonicalKey でソートして順序固定）/ 結合フラット化
- mkConcat: ∅零元 / ε単位元 / 右結合に固定
- mkStar: ∅*=ε, ε*=ε, (r*)*=r*
- 状態同一視キーは src/ast.ts の canonicalKey（正規化後の構造文字列）を使う

実装後、pnpm test:all が全部通ること（tests/linear.test.ts の状態数チェック含む）、
および pnpm bench:linear で状態数が入力長によらず一定であることを確認してください。
```

→ `pnpm test:all` が全緑になり、`pnpm bench:linear` で **状態数が一定・入力10倍で時間10倍（O(n)）** になれば完了。

## ③ 雑な層を丸投げ：パーサ / CLI（持ち帰り／講師デモ推奨）

`src/parser.ts` は `start` ブランチの時点で**既に完成品**として渡っている。
そのままこのプロンプトを投げると、動いているパーサをただ上書きしてしまうだけなので、
必ず次の手順で行うこと。

**基本は講師デモ推奨。** 本編（ハンズオン70分）の後半に組み込むと時間切れリスクがあるため、当日の参加者作業には含めない。参加者は持ち帰って各自の環境で試す（任意）。

**手順:**
1. `git rm src/parser.ts`（または `mv src/parser.ts src/parser.ts.bak` で退避）で完成品を一旦どかす
2. 下のプロンプトを Claude Code / Codex に投げて再生成させる
3. `pnpm test` が緑に戻ることを確認する
4. 失敗したら `git restore src/parser.ts` で完成品に復旧する（退避した場合は `mv src/parser.ts.bak src/parser.ts` で戻す）

「人間は設計、AI は道具」を体感する層。中身を理解せず投げてよい：

```
SPEC.md の AST（Re）に対して、正規表現文字列をパースして Re を返す再帰下降パーサを
src/parser.ts に実装してください。
対応構文: 連接 / 選択 | / 量化子 * + ? {n} {n,} {n,m} / グループ ( ) / 文字クラス [..] [^..] a-z /
ドット . / エスケープ \. \\ \d \w \s \n \t \r。
優先順位は | < 連接 < 後置量化子 < アトム。r+ → r·r*、r? → r|ε、r{n,m} → r^n·(r?)^(m-n) に脱糖。
mkAlt / mkConcat / mkStar / litChar / charClass / dot を使う。

以下は SPEC.md の対象外なので、黙って誤動作させず SyntaxError にすること（対処法をメッセージに含める）:
- ^ （行頭）/ $ （行末）
- \d \w \s \n \t \r 以外の英数字エスケープ（\b \D \1 など。特に \1-\9 は後方参照で正則言語を超えるため非対応）
- (?...) 拡張グループ（(?:...) (?=...) (?<name>...) など）
- 量化子でない裸の { }
非貪欲 *? +? ?? は「読み飛ばして無視してよい」（マッチ結果は貪欲版と同じなので言語は変わらない）。

tests/spec.test.ts が通ること（27件、未対応構文のエラーテスト含む）。
```

## ④ 発展（時間が余れば／持ち帰り）

**注意:** 交差・補集合をノードとして足す場合、`src/derivative.ts` の switch だけでなく
`src/ast.ts` の `Re` 型（判別タグ）と `canonicalKey`、`src/normalize.ts` の `mkAnd` / `mkNot`
（スマートコンストラクタ）も併せて拡張しないと、正規化・状態同一視が壊れる
（②で作った ACI 正規化の対象に新ノードが入っていないと、正規化されずに状態数が発散する）。

### ④-a 交差・補集合を追加する

```
src/derivative.ts に、交差 r&s と補集合 ¬r をノードとして追加し、
nullable と derivative の規則も足してください。
ν(r&s)=ν(r)∧ν(s), ∂c(r&s)=∂c(r)&∂c(s) / ν(¬r)=¬ν(r), ∂c(¬r)=¬∂c(r)。
src/ast.ts の Re 型と canonicalKey、src/normalize.ts の mkAnd / mkNot も
対応する形で拡張してください。
バックトラック型では難しい「交差・補集合」が、微分なら数行で入ることを確認したい。
```

### ④-b 持参した正規表現に対応させる（パーサ拡張）

当日の「実食」で対応構文外だった `^` `$` `\b` などを、実際に通るようにする持ち帰り課題：

```
src/parser.ts に、^ (行頭) $ (行末) \b (単語境界) への対応を追加してください。
- ^ / $ は src/ast.ts の Re に専用ノードを追加するか、既存の構文で等価表現できないかを検討し、
  SPEC.md の設計方針（正則言語の範囲に収める）と矛盾しない実装にする
- \b は文字クラスの境界判定として実装できないか検討する
  （後方参照 \1 のような正則を超える機能ではない点に注意）
- 実装したら、対応する nullable / derivative の規則、および tests/spec.test.ts の
  該当エラーテスト（^ $ \b を弾いていたテスト）の扱いを見直すこと
```

## 講師メモ（プロンプト運用の鉄則）

- **即興でプロンプトを書かない。** ①の連接 nullable 項を AI が落とすと `a?b` だけ壊れ、
  他テストが通るため原因特定に時間を溶かす。上の固定文をそのまま使う（リハ済み）。
- 生成 → `pnpm test` の**赤→緑ループを必ず参加者自身に回させる**（AI 丸投げで終わらせない歯止め）。
- ①で AI が `src/normalize.ts` や `tests/` まで書き換え始めたら止める。②の答え（ACI正規化）を
  先回りされると「まず壊れる→ACIで直す」の学びが消える。
- `②` の正規化は「まず壊れる（`pnpm bench:redos 16` の状態爆発検知）→ ACIで直す」を
  **手で握らせる**のが学びの核。ここは時短しない。
- ③（パーサ再生成）はデモの前に必ず `src/parser.ts` を退避すること。退避せず投げると
  完成品をそのまま上書きし、失敗時の復旧手順（`git restore`）が意味を持たなくなる。
